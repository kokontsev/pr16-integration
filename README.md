# Практическая работа 16

Интеграционное тестирование API.

Проверена полная цепочка HTTP → обработчик → сервис → PostgreSQL. Выбран вариант A из методички — Docker Compose. Для каждого теста создаётся отдельная схема и таблица с собственной последовательностью, в cleanup схема удаляется. Тесты проверяют CRUD, JSON, статусы, изменения в БД, ошибки, фильтр и страницы.

## Запуск на macOS или Linux

Go 1.27.1, curl, Docker Desktop. Каждая практика — отдельный Go-модуль. Команды выполняются из этой папки.

```bash
docker compose -p go-pr16 up -d
cp .env.example .env
set -a; source .env; set +a
go test ./...
go vet ./...
go run ./cmd/api
# в другом терминале после запуска БД
go test -count=1 -race -v ./integration/...
```

Файл `.env` читается оболочкой через `source`; автоматически сервер его не загружает. Порт API по умолчанию 8080. При одновременном запуске меняйте HTTP_ADDR, APP_ADDR (ПР9) или APP_PORT (ПР10).

## Проверки

Фактические результаты находятся в `evidence/`. Полные curl-команды и ответы — в `evidence/requests.txt` (для практик с HTTP-проверками). Тесты 15 и 16 записаны в `evidence/tests.txt` и `evidence/integration.txt`.

Маршруты: POST/GET `/api/v1/notes`, GET/PATCH/DELETE `/api/v1/notes/{id}`. Поиск `?q=Go`, страницы `?page=1&limit=20`. Тело создания: `{"title":"Go","content":"Текст"}`.

## Подготовка к защите

Интеграционный тест проверяет несколько слоёв вместе; unit-тест подменяет внешние зависимости и выполняется быстрее.

Docker изолирует версию и данные БД, обеспечивает воспроизводимость. Compose запускается отдельно, testcontainers управляет жизненным циклом из теста.

Схема test_<timestamp> создаётся для каждого кейса, соединение ограничено одним, search_path фиксирован, cleanup удаляет схему после остановки HTTP-сервера.

Проверяются порядок и значения обеих страниц фильтра Go с limit=1; пустой результат кодируется [] вместо null.

Миграции испытывают на отдельной БД; опасные изменения требуют проверки совместимости и резервного копирования.

Для CI нужна PostgreSQL service с healthcheck, DSN в окружении и go test -count=1 ./integration/.... Тесты не зависят от порядка.
